§3.5  —  四维位置图：Hermes 取舍全貌

四维评价位置图：Hermes 押注了什么、放弃了什么

不是打分表，不是说哪个更好 · 只回答「Hermes 把工程预算押在哪里、又牺牲了哪里」
四维 = L1 三支柱（GC / AC / CE）+ 入口治理（合规视角补 1 维）。绿 = 强选 / 黄 = 增强但有代价 / 红 = 部分放弃 — 颜色一眼看出 Hermes 的 4 维偏好。
Garbage Collection 动态化 L1 三支柱
强选 · 动态端
✓ 19 平台一致 + Nudge 自学 skill + Curator 后台清理
⚠ 代价：部署复杂 + 自学习虚假产出风险
Architectural Constraints 架构约束 L1 三支柱
部分放弃 · 偏信任端
✓ 三维弱：无 sandbox / 无 worktree / 无 step checkpoint；一维强：工具集黑名单 5 项
⚠ 代价：信任端押注用户自律
Context Engineering 上下文工程 L1 三支柱
增强 · 但有代价
✓ 热/冷记忆双层 + FTS5 双索引 + LLM 摘要
⚠ 代价：热记忆 token 越贵 + 14k schema 固定开销
入口治理 集中 ↔ 分治 三支柱外补 1 维
偏分治端
✓ 三套独立认证未统一中枢：ACP + Platform per-token + DM 审批
⚠ 代价：多入口边界缝隙（合规 / 审计风险）
📌 一句话总结
Hermes 选择了 强 GC 动态化 和 增强的 CE，让 agent 能跨入口复用记忆 / skill 并自动增长；代价是 AC 偏信任端 + 入口治理偏分治端，执行环境、工作区、入口认证都更依赖信任与后续治理。
