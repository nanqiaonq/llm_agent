C02 · §2.3 判定时机

判定时机：turn-end vs mid-tool

为什么 nudge 不能在 tool 调用中间触发？

✅ turn-end 触发：错位避免
  • turn 末是天然完整事件点——nudge 拿得到完整 tool 调用历史，prompt 才有信息可总结
  • 不抢 user-facing 模型 attention——`spawn_review` 在 response delivered 之后，主链路无干扰
❌ mid-tool 触发：错位演示 → 资源争抢
  • 两个 LLM API 调用并发——T2 还在跑，review agent 又同时调 model API
  • rate limit / context confusion 风险——同账户并发命中限流；review 拿到的对话不完整（T3 还没发生）
# Check skill trigger NOW — based on how many tool iterations THIS turn used.
_should_review_skills = False
if (self._skill_nudge_interval > 0
        and self._iters_since_skill >= self._skill_nudge_interval
        and "skill_manage" in self.valid_tool_names):
    _should_review_skills = True
    self._iters_since_skill = 0   # 触发后归零

# Background memory/skill review — runs AFTER the response is delivered
# so it never competes with the user's task for model attention.
if final_response and not interrupted and (_should_review_memory or _should_review_skills):
    self._spawn_background_review(...)
判定 = 守门人 · 时机 = 不抢 attention — 错位会引发结构性 bug
