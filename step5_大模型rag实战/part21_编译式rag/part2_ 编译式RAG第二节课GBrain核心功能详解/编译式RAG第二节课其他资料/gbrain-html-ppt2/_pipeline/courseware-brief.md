## 一、定位与铁律

- **课件性质**:GBrain **完整功能全景介绍**——一份自成体系、对任何人都讲得通的概念课件。
- **叙事主线(关键)**:GBrain = 一个完整的 brain layer,**两大核心能力平等完整展示**:
  - **能力一 · 建图(Connect)**:self-wiring 零 LLM 把 wikilink 织成 typed 知识图谱
  - **能力二 · 读+想(Read & Think)**:embedding 语义检索 + think 跨页综合出带引用+空白分析的答案
- **严禁残缺式叙事**:全课件**不得出现**"只用了一半""另一半""补全""承上启下""第一节/上一节没碰的"等措辞。两大能力都是 GBrain 的本事,完整呈现,不分已学/未学。讲师会口头补"建图上节课讲过",但课件自包含。
- **贯穿钩子**:"GBrain 如何让一堆笔记既**连得起来**、又**想得明白**"——从连接到思考。
- **HTML 课件铁律**:不嵌代码、不嵌真实截图、不嵌命令/参数/踩坑细节;所有机制用 HTML 原生可视化重画(架构图/对比/动画/交互)。

## 三、页面蓝图(约 24 页 · 9 模块)

### 模块 A · 开篇与背景(3 页)
- **A1 封面**:标题"GBrain:从笔记到会思考的大脑";副标题"编译式 RAG 的生产级实现";钩子"它不只给你页面,而是给你答案"。
- **A2 编译式 RAG 是什么** 🔴:传统向量 RAG(切chunk→embedding→机器索引→查询临时综合)vs 编译式 RAG(先编译成可读 wiki→查询直接读产物)。区别=黑箱机器索引 vs 可读可审计 wiki。交互:点击切换两条链路高亮。
- **A3 三层 + 三操作骨架**:三层 `raw/`(只读原料)·`wiki/`(LLM维护产物)·`CLAUDE.md`(规则层);三操作 `Ingest`·`Query`·`Lint`。视觉:三层金字塔 + 三操作循环。

### 模块 B · GBrain 全景与两大能力(3 页)
- **B1 GBrain 是什么 + 三层架构**:Storage(存)/Graph(连)/Retrieval(取)三层协同支撑顶层 think。
- **B2 两大核心能力总览** 🔴(纲领页):左"建图 Connect"(self-wiring→知识图谱)+ 右"读+想 Read&Think"(检索+综合→带引用答案)。视觉:一个**完整点亮**的大脑,左半连接发光、右半思考流出,**两边都亮**。交互:点左半/右半作为后续模块导航入口。
- **B3 两根轴 + 核心论断**:brain(数据库)⊥source(git);git markdown=源真相,数据库=编译产物(类比源码vs可执行文件)。

### 模块 C · 能力一:建图 self-wiring(4 页 · 充分展开)
- **C1 建图的起点:你怎么声明关系**:人在 markdown 写 `[[companies/nexaflow]]` + "founder of"措辞;关系是人显式写的、不是机器猜的。视觉:真实 markdown 高亮 wikilink + 语义动词。
- **C2 动态建图演示:看图自己长出来** 🔴🔴🔴(全课件第一记忆锚点):用 case-3 真实数据(3公司 NexaFlow/SparkField/AlphaVentures + 3人 Alice/Bob/Carol,16条边,4类型)。初始6孤立节点→点"运行 self-wiring"→逐条扫描markdown发现wikilink→有向边逐条飞出带类型标签(founded/works_at/invested_in/advises 四色)→边数0→16+类型柱状图同步→角标恒亮"LLM 0次·确定性·$0.00"→终态彩色typed图谱。增强交互:悬停边→高亮源markdown行(溯源);点节点→亮出其所有边;"删一条wikilink"→对应边消失(图是markdown实时镜像);"重跑"→图一模一样(确定性)。三句话:①关系是你写的不是机器猜的②零LLM零成本③改一行markdown图就跟着变。
- **C3 零 LLM 的确定性与可追溯**:正则规则(正文wikilink+动词→类型;frontmatter字段→映射);四类型;零LLM/确定性/每条边可溯源到行。视觉:点边→高亮源行动画。
- **C4 self-wiring vs GraphRAG**:解析显式链接(确定/可审计/本地)vs LLM抽实体推关系(非确定/需图库+LLM);为不同输入设计、非优劣。反例:《圣诞颂歌》纯散文 GBrain 建0边(设计使然)。视觉:对比矩阵+两种输入。

### 模块 D · 支撑层 Storage(2 页 · 读想能力的存储底座)
- **D1 源真相 vs 编译产物双轨**:改markdown数据库不自动更新、必须重编译(物化视图直觉)。视觉:git左轨→单向编译箭头→DB右轨,强调"改左不自动追右"。
- **D2 两引擎一契约 + embedding 是什么**:PGLite(嵌入式WASM/零服务器/个人)vs Postgres(团队/生产),一套 BrainEngine 契约换引擎不换代码;embedding=文本变语义坐标(方向近=语义近)。视觉:引擎对照+语义空间示意。

### 模块 E · 支撑层 Retrieval(3 页 · 读想能力的检索底座)
- **E1 为什么要混合**:BM25只认字面(漏同义/跨语言)vs 向量抓语义(对精确词钝),两路互补。视觉:两盲区圆+交集。
- **E2 三路合流 HNSW+BM25+RRF**:向量(HNSW近邻)+关键词(BM25字面)并行→RRF融合。视觉:一查询分两路并行→汇入RRF→统一排名。
- **E3 RRF 为什么不能直接加分** 🔴(核心机制):两路量纲不可比(BM25≈2.9 vs 向量≈1.0,直接加被BM25主导)→RRF只看名次1/(k+rank)两路平权。交互:滑块调两路名次,实时看RRF分,演示平权。

### 模块 F · 能力二:读+想 综合(3 页)
- **F1 search 给页面 vs think 给答案** 🔴(高峰):同句"明天见Alice前我该知道什么":search甩5页要你自己读;think替你读完跨页综合成带引用答案。交互:点击切换 search(页面列表)↔think(成文答案+citation)。
- **F2 空白分析 gap:最该先看的** 🔴(差异化亮点):think末尾诚实告诉你"还不知道什么":过期信息/无引用论断/自相矛盾三信号;先看gap再看正文。视觉:三信号卡片各配"你该做什么"。
- **F3 find_trajectory:时序复利**:一次问出"指标怎么变/团队什么样/承诺了什么",省去分别查再对齐时间线。视觉:时间轴汇聚成一个答案。

### 模块 G · 生态(2 页)
- **G1 51 skills vs 约90 MCP tools**:两维度不是一个数;skills=指令层(prose工作流·WHAT)、tools=执行层(类型化API·HOW),skills调用tools。视觉:两层对照+调用箭头。
- **G2 schema 包 + Minions 梦循环**:schema让大脑认识知识类型(person/company…);Minions夜间自动维护(去重/修引用/检测矛盾)。视觉:schema类型图谱+夜间维护循环。

### 模块 H · 判断力 benchmark(3 页)
- **H1 两个 benchmark 严禁混引** 🔴:LongMemEval R@5 97.6%(公开/keyword-only/可复现)vs BrainBench P@5 49.1%(厂商自建虚构世界/LLM judge);不在一个坐标系。视觉:两根异纹理柱+红色DO NOT MIX;hover看口径。
- **H2 成本贵 ≠ 质量差**:编译式约21×token(贵因think多跳综合),但换来跨源综合质量/可读知识库/可溯源,不是用更高成本换更低成本。视觉:成本轴vs质量轴两独立维度。
- **H3 三维权衡:一把判断的尺**:检索质量(高/可复现)/查询成本(高/21×)/适用场景(稳定知识+需深综合才划算)。视觉:三维雷达或决策树。

### 模块 I · 收尾(1 页)
- **I1 从笔记到会思考的大脑**:回顾GBrain两大能力(连接+思考);真正带走的是一把判断的尺——拆开任何RAG/记忆系统的存储/检索/综合层、看懂benchmark诚不诚实、判断成本值不值。视觉:全景回顾+尺子隐喻。**不提"补全"。**
