51 skills vs 约 90 MCP tools：两个维度

两个数字测的不是同一件事——skills 是指令层（WHAT），tools 是执行层（HOW），skills 调用 tools

51
Skills · 指令层
WHAT to do · prose 工作流 · 人类可读
Operator 手写的文本工作流文件，描述"做某件事的步骤是什么"
带触发词，可被 AI 按语义匹配激活
本身不是可执行代码，读它你能懂它要干嘛
示例：academic-verify skill — 一段带触发词的文本，描述"如何核验一条学术主张"的工作流步骤
↓
skills 调用 tools 完成操作
↓
约 90
MCP Tools · 执行层
HOW to do it · 类型化 API · 带 inputSchema
可被调用的类型化接口，带明确 inputSchema，真正读写页面、执行搜索
v0.42.44.0 实测 90 个（随小版本浮动，README 数字过时）
publish_skills=true 时 skills 也暴露为 tools，故约 90 > 纯 CRUD 数
示例：get_page tool — 带 inputSchema: {slug: string} 的接口，真去执行"按 slug 读一个页面"
51 和约 90 不矛盾——它们是同一系统的两个切面，测的根本不是同一件事。别信 README 数字，以自己环境的实测为准——文档里的 skills / tools 数字常滞后于代码，真实数量要在本地数一遍。
