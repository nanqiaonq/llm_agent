判断力 benchmark — 三维权衡

三维权衡：一把判断的尺

检索质量 / 查询成本 / 适用场景——三维一起看才知道值不值

01
检索质量
▲ 高 · 可复现

混合检索（HNSW 向量 + BM25 关键词 + RRF 平权）兼顾语义与字面，LongMemEval R@5 达 97.6%，结果可独立复现。知识图谱保证跨页溯源，每条引用可追到原始 markdown 行。

适合：需要"找对、找全"的知识型查询
02
查询成本
▲ 高 · ~21× token

think 做多跳综合推理，跨多个 wiki 页读取、合并、生成带引用答案，token 消耗约是单次 search 的 21 倍。成本高是功能的必要代价，而非系统效率问题。

判断：高频简单查询用 search；深综合用 think
03
适用场景
▶ 稳定知识 + 深综合

最匹配场景：知识相对稳定（技术规范/会议记录/研究笔记）且需要跨源综合（关系梳理/趋势汇总/多线对齐）。实时事件、一次性搜索、纯关键词命中——用传统 RAG 或直接搜索更划算。

甜区：稳定知识库 + 需跨页深度综合
甜区
稳定知识 + 需深综合 才划算：每次查询都在"消耗"积累的编译成本，综合得越深、省去的手工对齐越多，ROI 越高
不适用
实时动态信息 / 高频简单关键词查询 / 知识库内容极不稳定（频繁重编译成本高）→ 传统 RAG 或直接搜索更合适
