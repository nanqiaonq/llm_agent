答案抖动：生成层的随机，两种范式都有

点「再问一次」——看同一个问题如何给出两份不同的回答

用户提问 「编译式 RAG 的核心优势是什么？请简要说明。」
第一次回答
编译式 RAG 的核心优势在于将知识预先编译为结构化 wiki，避免每次查询重复消化原始资料。 查询时直接命中已提炼的产物， 跨源合成质量更高、结论更稳定， 且产物人类可读、可审计。适合知识稳定、需要跨源对齐的场景。
第二次回答
编译式 RAG 的主要价值在于一次编译、长期复用，降低了查询期的重复消化成本。 它把知识固化成 可持续维护的互链 wiki， 让 agent 查询时无需重读原始文档， 从而提升回答的一致性与可追溯性。
点「再问一次」，第二次回答与第一次有细微出入——三层随机源各自贡献了一点「抖动」
层 1 · 检索召回
检索有随机性
向量相似度前 k 名的排列每次略有差异，捞到的片段集合不完全相同，导致「素材池」第一步就不同了
相关片段 A / B / C → 下次变成 A / B / D
层 2 · 片段排序
排序有随机性
检索结果在拼入 prompt 时的顺序影响模型的注意力分布，相同片段排序不同往往得到不同侧重的回答
片段 A→B→C 与 C→A→B 引发不同的回答侧重
层 3 · 模型生成
生成有随机性
LLM 的 temperature>0 使得相同 prompt 每次采样路径略异，措辞、结论侧重、引用选择都会漂移
「核心优势」被归纳为「复利资产」vs「消化效率」
⚠
答案抖动主要来自生成层的随机性，只在需要模型当场归纳的开放问题上显现。 它是两种范式共有的现象，与中间产物是机器索引还是 wiki 无关——编译式查询同样会有措辞漂移。
