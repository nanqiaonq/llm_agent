# 重跑速查 — 把服务器清回某个状态

> **用途**：每次想从头再跑一遍部署流程时，用这份清单把服务器清回某个起点。
>
> **不会动的东西**(单次工作，无需重做)：
> - 服务器基线包(`python3.12 / git / curl / snapd`)
> - 本机 `~/.ssh/config` 的 `myagent` alias
> - 公钥免密(`~/.ssh/authorized_keys` 里的本机公钥)
> - 服务器系统用户 `ubuntu`、UFW 规则
>
> **场景对照**：
> - 改了本机 `main.py` 想重新部署 → **场景 A**
> - 整个 6 章跑过一次想再练一次 → **场景 B**

---

## 场景 A：清回到第二章起点(只清应用层)

适合：代码刚改完想重新 scp 上去，或者第二章操作过程出错想重来。**保留 systemd / nginx / 证书**(因为它们指向的应用目录会跟新代码兼容)。

SSH 上服务器跑：

```bash
# 1. 停掉手动跑的 uvicorn(后端)+ http.server(临时前端)
pkill -f "uvicorn main:app" 2>/dev/null
sudo pkill -f "http.server 12233" 2>/dev/null

# 2. 清掉旧 ai-todo 应用目录(整个 /home/ubuntu/ai-todo)
sudo rm -rf /home/ubuntu/ai-todo

# 3. 清中间产物
rm -f /tmp/ai-todo.tar.gz /tmp/ai-todo.env

# 4. 确认全清干净
ls /home/ubuntu/         # 期望:没有 ai-todo 目录
ls /tmp/ai-todo.* 2>/dev/null && echo "还有残留" || echo "/tmp 已清空"
```

清完之后退出服务器，回本机跑课件 **2.1 scp 上传代码** 即可重启流程。

---

## 场景 B：清回到第一章末尾(应用层 + systemd + nginx + 证书 + logrotate 全清)

适合：整门课跑通一遍后想再练一次完整流程。

SSH 上服务器跑：

```bash
# 1. 停掉 + 禁用 ai-todo systemd 服务 + 杀残留临时前端
sudo systemctl stop ai-todo 2>/dev/null
sudo systemctl disable ai-todo 2>/dev/null
sudo rm -f /etc/systemd/system/ai-todo.service
sudo systemctl daemon-reload
sudo pkill -f "http.server 12233" 2>/dev/null   # 杀第二章起的临时前端 web server

# 2. 清应用目录 + 临时文件
sudo rm -rf /home/ubuntu/ai-todo
rm -f /tmp/ai-todo.tar.gz /tmp/ai-todo.env

# 3. 清 nginx 站点配置(保留 nginx 本身和 default 兜底)
#    注意:课件第 4.2 节创建的站点文件叫 myagent-lab.online,不是 ai-todo
sudo rm -f /etc/nginx/sites-enabled/myagent-lab.online
sudo rm -f /etc/nginx/sites-available/myagent-lab.online
# 清第 4.3 节加的限流 zone 定义文件(放在 conf.d/ 下,跟 site config 分开)
sudo rm -f /etc/nginx/conf.d/ai-todo-limits.conf
# 恢复 default 站点启用(第 4.2 节把它停用了,要把软链补回来,否则 80 端口没人接)
sudo ln -sf /etc/nginx/sites-available/default /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx

# 4. 清 logrotate 规则
sudo rm -f /etc/logrotate.d/ai-todo

# 5. 证书选择(看你练习节奏)：
#    - 保留证书：跳过这一步(推荐多次练习用,避免命中 Let's Encrypt 速率限制)
#    - 完全清干净:取消下一行注释
# sudo certbot delete --cert-name myagent-lab.online
```

清完之后退出服务器，回本机跑课件 **2.1 scp 上传代码** 重启完整流程。

---

## 三个常见坑

1. **Let's Encrypt 速率限制**：同一域名 7 天内最多 5 次成功签发。多次练习时**不要清证书**(把场景 B 第 5 步注释保持)，certbot 第二次跑时会自动复用已有证书，跳过签发。

2. **systemd 残留状态**：删 unit 文件之前必须先 `disable` + `daemon-reload`，否则下次 `enable --now ai-todo` 可能报 `Failed to enable unit: Unit file is masked` 之类的状态错误。

3. **uvicorn 后台残留**：手动 `0.0.0.0:8080` 跑过的 uvicorn 在 SSH 终端关闭后并不会立刻退出(取决于 shell 是否发 SIGHUP)。重跑前先 `pkill -f "uvicorn main:app"`，避免新进程因为端口占用起不来。

## 完整重置(慎用)

把服务器**真的当 100% 全新**:除了上面场景 B 之外，**额外**把基线包和 SSH 配置也回退。

> ⚠️ 这一段会让本机原配的 `ssh myagent` 暂时不能用——执行前确认你**记得服务器密码**，否则只能用云控制台 VNC 进来。

```bash
# 1. 先跑完场景 B 所有步骤

# 2. 卸载基线
sudo apt remove -y nginx certbot python3.12-venv git
sudo apt autoremove -y
sudo snap remove certbot 2>/dev/null

# 3. 清服务器端授权 key(本机的 myagent 公钥)
# 警告:执行这条之后,本机 ssh myagent 会回退到要密码登,直到你重跑课件 1.6 重新分发公钥
> ~/.ssh/authorized_keys
```

这种场景几乎不需要——一般想"再练一次"用场景 B 就够了，基线包重装一次成本高且没意义。
